## 2025-05-18 - EF Core Query Parameterization and Indexing on Existence Checks
**Learning:** Using `Expression.Constant` in dynamic LINQ queries bakes literal values into the expression tree, preventing EF Core from parameterizing queries and reusing cached execution plans in its Compiled Query Cache. Using `EF.Property<TProperty>` with closures enables parameterized queries (`@p0`) that EF Core can compile once and reuse. Additionally, missing database indexes on un-queried fields like `Email` cause full table scans (`O(N)`) during API validations.
**Action:** Always prefer `EF.Property` and `.AsNoTracking()` for dynamic entity property checks, and ensure fields checked during API validation (like `Email`) have explicit database indexes configured in EF Core `ModelBuilder`.
